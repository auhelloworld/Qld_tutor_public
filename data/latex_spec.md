# 题库数学符号与 LaTeX 编写规范

## 核心原则：JSON 中的反斜杠规则

这是最容易出错的地方。记住以下规则：

1. **LaTeX 中的单个反斜杠 `\` 在 JSON 里写成 `\\`**。例如 `\frac` 写成 `\\frac`。
2. **LaTeX 中的双反斜杠 `\\`（用于多行公式/环境换行）在 JSON 里写成 `\\\\`**。
3. **将单个反斜杠命令（如 `\frac`）误写为 `\\\\frac` 是错误的**。

| 你想要的最终字符串 | JSON 文件中应该写 | 说明 |
|---|---|---|
| `\frac{1}{2}` | `\\frac{1}{2}` | 单个反斜杠命令 |
| `\sqrt{16}` | `\\sqrt{16}` | 单个反斜杠命令 |
| `\times` | `\\times` | 单个反斜杠命令 |
| `\overline{6}` | `\\overline{6}` | 单个反斜杠命令 |
| `\pi` | `\\pi` | 单个反斜杠命令 |
| `\\` (换行符) | `\\\\` | 用于 `aligned` 等多行环境的换行 |

**为什么会出现双反斜杠错误？** 作者在编辑器里看到 `\frac`，心想"JSON 需要转义反斜杠"，于是加了两层变成 `\\\\frac`。这在 JSON 解析后会变成 `\\frac`，被 KaTeX 识别为 `\\`（换行）加上 `frac`，从而导致渲染错误。正确做法是用 `\\frac`，在 JSON 解析后还原为单个反斜杠 `\frac`。当需要 `aligned` 换行时，才需要使用 `\\\\`。

**验证方法：**
```python
import json
# JSON 中 \\frac → 解析后得到 \frac（单个反斜杠，KaTeX 可识别）
data = json.loads('{"q": "$\\\\frac{1}{2}$"}')
print(repr(data['q']))  # 输出: '$\\frac{1}{2}$'  ← repr 显示 \\ 即单个反斜杠
```

## 一、LaTeX 分隔符规范

只用 `$...$`（行内数学）和 `$$...$$`（显示数学）。

```json
// ✅ 正确
"question": "Solve $2x + 5 = 13$ for $x$."
"question": "The quadratic formula is $$x = \\frac{-b \\pm \\sqrt{b^2 - 4ac}}{2a}$$"

// ❌ 错误 — 不要用 \(...\) 或 \[...\]
"question": "Solve \\(2x + 5 = 13\\) for \\(x\\)."
```

原因：虽然前端 `preprocessMarkdown` 支持将 `\(/\)` 和 `\[/\]` 转换为 `$`/`$$`，但多做一层处理就多一层风险。坚持只用 `$...$`。

## 三、Unicode 字符 vs LaTeX 命令的选择

**规则**：在 `$...$` 数学块内，优先使用 LaTeX 命令。

| 场景 | ✅ 推荐 | ❌ 避免 |
|---|---|---|
| 乘法号 | `$2 \\times 3$` | `$2 × 3$` |
| 度数 | `$90^\\circ$` | `$90°$` |
| 根号 | `$\\sqrt{16}$` | `$√16$` |
| 分数 | `$\\frac{1}{2}$` | `$½$` |
| π | `$\\pi$` | `$π$` |
| 除号 | `$a \\div b$` | `$a ÷ b$` |

### ⚠️ 特别注意：√（根号）

`√`（U+221A）是 **唯一 KaTeX 不支持的 Unicode 数学符号**。使用 `√` 会触发 KaTeX 警告且渲染缺少根号横线（变成 "√20" 而非 "√̅2̅0̅"）。

```json
// ❌ 错误 — KaTeX 警告，无根号横线
"$√{20}$"

// ✅ 正确 — 完整的根号渲染
"$\\sqrt{20}$"
```

### 哪些 Unicode 字符在数学模式中安全？

KaTeX 完全支持以下 Unicode 字符：
- `×`（乘号）— 与 `\times` 等价，但为了一致性仍推荐 `\times`
- `°`（度符号）— 与 `^\circ` 等价，但为了一致性仍推荐 `^\circ`
- `π`、`θ`、`α`、`β` 等希腊字母 — 与 `\pi` 等等价，但推荐用 LaTeX 命令
- 上标数字：²、³（但 `x^2` 更规范）

**建议**：已有 Unicode 写法的存量题目（×、°、π）可以不改，但**新题目一律用 LaTeX 命令**。只有 `√` 必须改为 `\sqrt{}`。

## 四、百分号 `%` 的处理

在 KaTeX 数学模式中，`%` 是 TeX 注释字符，**必须转义为 `\%`**。

```json
// ✅ 正确
"question": "A $15\\%$ discount is applied."
// 输出: "A 15% discount is applied."

// ❌ 错误 — 裸 % 会被 KaTeX 当作注释，其后的内容全部被忽略
"question": "A $15%$ discount is applied."
// 输出: "A 15"  ← % 之后的内容丢失！
```

快速参考表中已有正确写法：`$15\\%$ → "15\\%$`。

## 五、数学模式的常见陷阱

### 陷阱 1：`$...$` 不能嵌套

JSON 中 `$` 被用作数学分隔符，嵌套会导致解析错误。

```json
// ❌ 错误 — 嵌套 $
"$The value of $x$ is 5$"

// ✅ 正确 — 分别包裹
"The value of $x$ is 5"
```

前端 `preprocessMarkdown` 使用非贪婪匹配 `\$([\s\S]*?)\$`，所以 `$x$` 中的第一个 `$` 结束外层数学块，`x$` 中的 `$` 又开启一个新块，导致预期外的结果。

**规则**：不要在 `$...$` 内部再放 `$`。需要同时显示数学和文本来回切换时，用多个相邻的 `$...$` 块。

### 陷阱 2：数学模式中的空格被忽略

KaTeX 数学模式会忽略所有普通空格。需要空格时必须用 `\ `、`\quad` 或 `\text{}`。

```json
// 以下三个效果相同（都是 "ab"）
"$a  b$"
"$a b$"
"$a     b$"

// 需要空格时
"$a \\quad b$"         → "a   b"（宽空格）
"$a \\, b$"            → "a b"（窄空格）
"$a \\text{ } b$"      → "a b"（文本空格）
```

**规则**：KaTeX 数学模式中的格式（间距、换行）需要用显式命令控制。

### 陷阱 3：`_` 和 `*` 在 `$...$` 内外含义不同

| 字符 | 在 `$...$` 内 | 在 `$...$` 外（Markdown） |
|---|---|---|
| `_` | 下标：`$x_1$` → x₁ | 斜体：`_italic_` → *italic* |
| `*` | 星号运算符：`$a * b$` → a*b | 加粗：`**bold**` → **bold** |
| `^` | 上标：`$x^2$` → x² | 纯文本 `^` |

```json
// ❌ 期望下标，但变成了斜体
"x_1 的值是 5"

// ✅ 加 $ 明确表达数学模式
"$x_1$ 的值是 5"
```

### 陷阱 4：KaTeX 不支持的 LaTeX 命令

以下常见 LaTeX 命令 **不被 KaTeX 支持**，可能会静默失败或报错：

| 不支持的命令 | KaTeX 替代方案 | 说明 |
|---|---|---|
| `\begin{align}...\end{align}` | `$$\begin{aligned}...\end{aligned}$$` | 用 `aligned` 环境 |
| `\begin{equation}` | `$$...$$` | 行间数学即可 |
| `\label{}`, `\ref{}` | 不支持 | KaTeX 无交叉引用 |
| `\over` | `\frac{}{}` | 推荐始终用 `\frac` |
| `\choose` | `\binom{}{}` | 组合数用 `\binom` |
| `\colon` | `:` | 冒号直接写 |
| `\not=` | `\neq` | 不等于 |
| `\bf`, `\it` | `\mathbf{}`, `\mathit{}` | 用现代字体命令 |

**规则**：坚持使用本规范速查表中列出的命令。如果用了表外的命令，先用 KaTeX 测试。

### 陷阱 5：美元符号的处理

当题目中出现美元金额时，推荐**在数学块内部用 `\$`**，或者在非数学文本中将其转义为 `\\$`。

```json
// ✅ 推荐 1：用 \$ 在数学块内渲染美元符号
"question": "A jacket costs $\\$80$ and is on sale at $15\\%$ off."

// ✅ 推荐 2：用 \\$ 在普通文本中转义美元符号
"question": "A jacket costs \\$80 and is on sale at $15\\%$ off."

// ❌ 错误 — $ 未被转义，会被错误配对，导致 and is on sale... 变成数学模式
"question": "A jacket costs $80 and is on sale at 15% off."

// ❌ 严重错误 — 单个未转义的 $ 符号（导致排版灾难崩溃）
"answer": "$48"
"question": "Store A is better by $45"
```

**为什么单个未转义的 `$` 符号是致命的？**
如果在 JSON 字符串中裸写了单个 `$` 符号（例如价格 `$48`），前端解析器会认为这是数学公式的**起点**。因为它在当前字段中找不到第二个 `$` 来闭合，它会把页面上**下一个出现 `$` 的位置之前的所有网页文本**全部当作公式渲染，导致页面文字变成没有空格的斜体，排版完全崩溃。因此，非数学公式的 `$` 符号**必须转义写为 `\\$`**。

**流程说明**：`$\\$80$` 或 `\\$80` 被 JSON 解析后得到 `$\$80$` 或 `\$80`。前端 `preprocessMarkdown` 将 `\$` 转为 `&#36;`（HTML 实体）以防止其被当作数学分隔符，随后 Markdown 渲染器或 KaTeX 将其正常显示为 `$80`。

## 六、步骤（steps）文本的格式

**规则**：步骤文本中如有数学表达式，**必须加上 `$...$` 分隔符**。不要依赖前端的 auto-wrap 启发式。

```json
// ✅ 正确
"steps": [
  "Divide 48 by 2: $48 \\div 2 = 24$",
  "$24 \\div 2 = 12$",
  "Final answer: $2^4 \\times 3$"
]

// ❌ 危险 — auto-wrap 不可靠
"steps": [
  "48 = 2^4 × 3"
]
```

### 关于 auto-wrap（Fix 5 之后）

前端有一个 fallback 机制：对没有 `$` 分隔符但含有 `^` 或 `_` 的文本，自动包裹 `$...$`。但 **Fix 5 后条件收紧**：

- ❌ `a^m × a^n = a^(m+n)` — 有 `^` ✅，但无数字 ❌，无 `\\` 命令 ❌ → **不触发**
- ✅ `2^3 = 8` — 有 `^` ✅，有数字 ✅ → 触发
- ✅ `$a^m \\times a^n = a^{(m+n)}$` — 手动加 `$` ✅

结果：`a^m` 会渲染为纯文本 "a^m"，`^` 显示为文字箭头（上箭头），而非指数。

**所以在 `steps` 中永远手动加 `$`。**

## 八、自动化语法与渲染自检

为了确保新加入的习题 100% 不会出现 LaTeX 语法或美元符号排版引起的渲染错误，我们在 `scripts` 目录下提供了一个自动校验脚本 [check_exercises.py](../scripts/check_exercises.py)。

### 1. 校验脚本的检测规则
脚本会自动扫描题库，并严格检查以下几点：
1. **未闭合美元符号检测**：检测单行内是否有奇数个 `$` 符号（例如裸写价格 `$48`），防止其破坏页面后续的所有排版。
2. **大括号 `{ }` 配对检测**：公式内的参数括号 `{` 和 `}` 必须严格成对，防止 KaTeX 报错崩溃。
3. **`\left` 与 `\right` 配对检测**：自适应括号大小命令必须成对。
4. **数学块内的 Unicode 根号 `√`**：数学块内不能含有 Unicode `√`，必须替换为 `\\sqrt{}`。
5. **解题步骤（steps）未加 `$`**：检查 `steps` 中是否含指数（`^`）、下标（`_`）或 LaTeX 命令但未用 `$` 括起来，防止排版被拉伸变形。
6. **非法 LaTeX 命令检测**：如 `\\over`、`\\choose`、`\\begin{equation}` 等 KaTeX 不推荐或不支持的命令。

### 2. 运行自检脚本
在添加或修改任何 JSON 题库数据后，请在项目根目录下运行以下命令进行自检：

```bash
python3 scripts/check_exercises.py
```

如果控制台输出中包含 `❌` 报错，请根据提示中的 `Exercise ID` 和错误原因在 JSON 中进行修正，直至控制台输出 `Total issues found: 0` 方可提交。

## 附录：渲染管线说明（供参考）

学生端渲染流程：

```
JSON 数据 → JSON.parse → preprocessMarkdown() → remark-math → rehype-katex → HTML
```

1. **JSON.parse**：`\\frac` → `\frac`（单反斜杠还原）
2. **preprocessMarkdown**：保护 `$...$` 块内部不被转义，转换 `\(/\)` 和 `\[/\]` 为 `$`/`$$`
3. **remark-math**：识别 `$...$` 和 `$$...$$` 为数学块
4. **rehype-katex**：将数学块渲染为 HTML 数学符号

**关键**：所有 LaTeX 命令在 `$...$` 内部由 KaTeX 渲染，学生**只看到渲染后的数学符号**，不会看到 `\times`、`\circ`、`\sqrt` 等原始代码。
