# Core workflows

## Home page and navigation

- An unscoped home-page visit does **not** auto-select the first Year 7 Mathematics topic or start an arbitrary question. The student explicitly starts **Today Study** or chooses a subject, year/unit, and topic. Scoped links from Today, the Error Book, diagnostics, and results retain their URL subject/year/unit/topic context; stored browser preferences are only the fallback when the URL does not provide that scope.
- **Today Study** is the primary recommended action. Manual curriculum browsing remains available for free-choice practice, while Guided Practice, assessment, progress, advanced tools, and parent tools are grouped into secondary disclosures so they do not compete with the daily task.
- Desktop uses the persistent study-navigation sidebar. At tablet and phone widths the same controls move into a slide-out **Study navigation** drawer that can be opened from the menu button and closed with the button, overlay, or Escape. Choosing a topic closes the drawer and returns the phone viewport to the practice area.
- Curriculum, Today-plan, Today-session-progress, and exercise-loading failures are distinct from a genuinely empty topic. Student-facing recovery states explain that saved progress is unchanged and provide **Retry** actions instead of silently removing the card or reporting that no content exists.

## Practice and guided learning

- Browse the curriculum by learning group or official strand, then select a topic and difficulty.
- Use standard practice or Guided Practice, which combines concept cards, lesson content, graduated help, answer feedback, corrective retries, scaffold fading, and session summaries.
- Before the first answer, Guided Practice exposes only solution-safe concepts, goals, rules, and vocabulary. Current-question worked steps, results, answers, and answer-bearing practice blocks remain hidden until the student has attempted the item.
- The first scored error requires one short correction on the same question before **Next** is enabled. A successful correction or a second unsuccessful attempt may then continue; correction never adds another question to the session target.
- Each question keeps its highest support level: `0` independent, `1` light hint, `2` step/dialogue help, `3` worked example, and `4` Show Answer. Retries cannot lower this value. Show Answer records level `4` only after the student confirms the reveal; cancelling the confirmation leaves the evidence unchanged. The answer comes from `/api/tutor/show-answer`, which needs one earlier answer attempt on the question. If the answer does not load, the evidence does not change. Reveal evidence cannot secure learning quality.
- The final two questions of a Guided session fade Concept, Example, Tutor Chat, and advanced help without increasing the session length. Selection stays in the active topic and prefers unseen items with a different representation, difficulty, or complexity. Both must be first-attempt, support-level `0` successes for the summary to report **Independent check secured**. The completion summary deliberately keeps only the success criterion, independent evidence, one short support-use explanation, and one next action; it no longer treats a solved-by-end percentage or help counts as mastery. Responses awaiting parent review are shown as **Pending**, not `0/0` evidence.
- A one-sentence self-explanation is required after a corrected success, scaffolded success, or low-confidence success, capped at two prompts per session and stored with the exact attempt.
- Answer multiple-choice, short-answer, reasoning, and multi-part questions. Supported items can include tables, graphs, geometry diagrams, scientific process/model diagrams, and interactive mathematical plots.
- After a mark, the answer input is read-only until the student selects **Try Again** (or, for a multi-part question, another part). A multi-part question stays on the part that was just marked. Unsent text of other parts is kept when the student changes parts.
- Use advanced lesson extensions where authored content is available.
- Request Socratic dialogue or hints without allowing the LLM to choose the curriculum path.

## Daily study, progression, and revision

- The home-page **Today Study** card opens a persistent `/today` session shell. Stable task IDs and a session bar preserve subject/year scope, progress, and the next action while the student moves through practice and Diagnostic routes. A home-page diagnostic recommendation opens this scoped Today shell rather than starting a context-free assessment route. On phones and tablets the Today card is in the closed Study navigation drawer, so the empty practice area also has a **Start Today’s Study** button. `/today` is one centred column: **Exit session** on the top line, then the goal, the progress and the main button, then one compact row for each step. It shows the year and subject and the topic names of each step. When the session is done, the finished steps fold under one line. Another subject starts from the home page: `/today` reads its subject from the URL only when it loads. The session bar stays at the top of each practice page.
- Today homework is scoped to the selected subject and year/unit. The separate home-page **Across all subjects** counter is an optional household-wide habit/quest activity goal; it is not the Today homework requirement. Completing the planned session can therefore be reported independently from meeting that optional cross-subject goal.
- Today Study has no question-count choice. Each step stops when the student shows the skill:
  - Past mistakes come first: at most 3 steps, in the order **due consolidation → transfer → retry → cause**. A cause step is a short reflection with no question; the other steps ask 1 question. A mistake that the student first makes today waits for tomorrow’s plan, so a wrong answer does not add a step today.
  - Review: at most 3 due topics. The student answers from memory first. A topic is done after one right answer with no help, or after 2 answers. A senior unit (Units 1–4) also gets this step; only topics of the selected unit can be due.
  - New topic: a short lesson and a worked example come first; they are not counted. The step stops when 3 of the last 4 answers are right with no help (at least 4 answers), or at 10 answers.
  - Topic choice: the plan suggests the first topic in teaching order that is not mastered and whose prerequisites are mastered. Only prerequisites in the same year or unit count, and a topic that the diagnostic found secure counts as met. So a topic that is not mastered blocks only the topics that need it. Before the first answer, the student can choose any topic of the year or unit (`topic_options`); a topic with open prerequisites names them but is not blocked. The first answer fixes the topic for the day. Prerequisites come from `sequence.prerequisites` in `data/curriculum/*/*.json`; a test checks that each prerequisite comes before its topic in `sequence`.
  - Final check: 2 questions, one on the new topic and one on a review or mistake topic. The day shows “goal met” only at 2 of 2.
  - The student does the steps in any order. The final check is `locked` until the other steps are done.
  - The day uses at most three topics. One topic slot is kept for the new topic, so a review can wait a day.
  - More practice (`more_practice`, optional, after the day is done): one more topic a day (`extra`: same stop rule, any topic except today’s new topic) and mixed practice (`mixed`: rounds of 4 questions on today’s topics, with no end). It does not change the day’s result.
  - Time: minutes per question come from the question types of each topic and the stage (Years 7–8, Years 9–10, Units 1–4). For example, Year 7 Maths is about 2.7 minutes a question and Methods Unit 1 about 4.9. These are estimates, not measured times.
- Spacing: a review topic moves at most one step per Brisbane day; the first answer of the day decides. Only a right answer with no help moves it forward. Help keeps the interval. A wrong answer moves it back one step.
- All Today steps run on one page: `/today/practice?…&today_task=<id>`, also the past-mistake steps. The page reads the step from the plan and asks the server before each next question; when the step is done, the student returns to `/today`. Help rules: a new topic offers help before the first answer; review, practice on your own and the mistake steps open help after the first answer; the final check has no help and no second try. After 2 right first tries in a row, a new topic stops offering help before the answer. On a wide screen (1100px and more) the help panel opens next to the question and stays in view; on a narrow screen it opens below and scrolls into view.
- Past-mistake steps on the Today page: the cause step shows the question, the student’s answer, the right answer and its steps (folded), the cause choices and an optional if–then plan. The transfer step and the later check ask a new question on the same idea (`tutorSuggest` mode `error_book`). A right first try with no help on a fair new question moves the Error Book item on at once (`/api/tutor/mistakes/resolve`, one request ID per answer), so leaving the page cannot lose it. A right second try is practice.
- The question card has an optional **How sure?** choice (`confidence` on `/api/tutor/mark`). A sure miss and a guessed right answer get one line of feedback. After a corrected or guessed right answer, the page asks for one sentence (“What made it work?”) before the next question, at most 2 times a day per browser. A right answer marked `guess` is weak BKT evidence (guess rate 0.5, as in the diagnostic) and does not count as right: not for mastery, Today steps and the final check, Error Book steps, or the Guided Practice independent check. Quests and reports still count it as a correct answer.
- **I don’t know** replaces Skip on the Today practice page. It records a scored miss (`gave_up` on `/api/tutor/mark`, error type `dont_know`) without the marker, gives no stars, and adds no Error Book entry. After two misses, or after **I don’t know**, the page shows the right answer and the steps of that question, with one more example folded below, then a new question. Question payloads carry no answer key: the mark response adds `correct_answer` and `solution_steps` only for a scored miss on the last try (`gave_up`, or `reveal_answer` from the page).
- A new-topic step keeps the mode of its first answer for the whole day, so progress today does not change its help rule or title.
- Free practice on `/` (TutorInterface) and Guided Practice (`/guided-practice`) do not run Today steps.
- A diagnostic reports curriculum areas: the strands, with Science Understanding split into Biological, Chemical, Earth and space, and Physical sciences. It asks about 12–18 questions (2–3 per area; 4–5 per English strand), with a hard cap of 24 responses. A diagnostic day schedules only that assessment instead of appending Error Book or focus practice, unless the student chose “Stop and don’t remind me”. Diagnostic result links retain subject/year and Today return context. Consolidation is never scheduled before `consolidation_due_at`.
- The Today Plan API keeps three evidence meanings separate: **completed** is unique-question volume, **supported progress** is a correct non-revealed response at support levels `0`–`3` (including non-revealed legacy rows whose support provenance is unknown), and **independent secured** is a first-response success with explicit support level `0` and no reveal. Repeated submissions of one `question_id` count once. The backend validates Today task date, subject, scope, kind, and topic/source before accepting task evidence, and persisted attempts prevent a retry from being promoted to a first attempt. A step can end without independent evidence (for example at 10 answers); the UI then says that more review is planned. A wrong answer never adds work today. `next_href` is the suggested next action; other open steps have their own links, so the student chooses the order. Each task also has `topic_names`, aligned with `topic_ids`, from the curriculum; an unknown topic falls back to its ID.
- Bayesian Knowledge Tracing (BKT), prerequisites, recommendations, daily-task selection, and spaced-repetition intervals are calculated locally and deterministically. Support levels `1`–`3` may inform the general BKT trajectory, but they are not mastery evidence. One rule decides **mastered** (`StudyRuleEngine.mastery_established`): at least 4 first answers with explicit support level `0` and no reveal, 3 right in the last 4 of them (the same "3 of 4 right on your own" as a Today new-topic step), and BKT at the mastery threshold on direct and on independent answers. Only the first answer to each question counts: a correction after feedback, or the same question again on another day, shows recall of that question. This rule controls the progress `status`, the curriculum ticks, Today's topic choice, prerequisite unlocks, forward-topic skipping, revision start, and revision due checks. It has no time decay: the current BKT estimate fades, but mastery stays until new answers break the rule (for example 2 wrong in the last 4); the revision schedule handles freshness. Direct diagnostic responses are stored at support level `0` and use the same rule; inferred diagnostic pseudo-evidence cannot satisfy it.
- The student dashboard shows scoped progress, study plans, recommendations, and topic-level learning status.
- The Error Book keeps confirmed mistakes active through an evidence-based five-stage closure path: **understand the cause → retry independently → answer a transfer question → complete spaced consolidation → close**. The first eligible transfer success schedules consolidation for three days later; a fresh eligible transfer-safe answer after that due time is required to close the mistake.
- Answering the original question correctly later is retry evidence, not closure: the source mistake remains Active at `needs_transfer`. Evidence-backed `closed` items and manually `dismissed` items are counted and displayed separately; dismissal hides an item without claiming mastery.
- A card at `needs_transfer`, or at `needs_consolidation` when it is due, has a **Do a transfer question** or **Do the spaced check** button. Only this one-item quiz (or the same step in Today’s Study) counts as closure evidence; **Redo question** is practice. A qualifying answer moves the item on right after the answer, not at the end of the quiz. The quiz start box shows how many items are ready to advance. Ready items come first, and the summary gives a reason for each correct answer that counted as practice only.
- A multi-part part that is marked wrong is a confirmed mistake, also while other parts are blank or pending. The attempt keeps `part_error_history`, so a later fix of that part does not remove the Error Book item; the item shows the wrong part answers. Mastery (BKT) still uses the whole-attempt outcome. Older attempts get this item only when their question is written again.
- Student reflections use one subject-aware cause taxonomy shared by normal practice and the Error Book for Maths, English, and Science families. An existing `reflection_type` is reused as the Error Book cause, so the student is not asked twice. This student reflection is separate from the system-generated, fine-grained error classification.
- Quest rows include direct scoped learning actions: Error Book quests open the Error Book, the daily-goal quest opens Today Study, and accuracy/streak quests open the main Exercise page. The Interleaver quest has no preselected jump: choose strands during practice and use **Claim** after reaching the target. The Error Book quest completes after the first eligible transfer-safe success for one unique source mistake that day; original-item retries, duplicate attempts, ineligible variations, Show Answer submissions, and later consolidation checks do not add quest progress.
- Curated misconception libraries use deterministic, subject-aware predicates for supported Maths and English patterns. A targeted worked example is offered only when the corresponding evidence predicate matches.
- Speed Round provides separate timed fluency practice. Its attempts are kept out of normal mastery and mistake evidence.

## Weekly learning review

- Students can open **My Weekly Learning Review** directly from the home-page **Progress** disclosure or from the prominent card near the top of `/dashboard`. The dedicated page is `/weekly-report`; the existing Dashboard analytics and parent views remain separate.
- A formal report uses a fixed **Monday–Sunday calendar week in `Australia/Brisbane`**, not a moving seven-day window. The current week is labelled in progress, and the selector exposes the current week plus the previous 11 weeks. Historical reports are derived from persisted attempt evidence for those fixed boundaries rather than copied into a second statistics snapshot table.
- The report combines all subjects for the overview, then provides subject-level evidence. It shows scored attempts, Brisbane-local active days, first-try independent successes, supported successes, revision and mistake closure, self-explanations, a weekly bright spot, one area to keep building, and one actionable next step.
- Evidence language is deliberately conservative. A topic needs at least two scored attempts before it can be named as a bright spot or focus; fewer than five attempts leaves the overall report marked as limited evidence. Empty weeks invite one short practice set, and previous-week comparison is descriptive rather than labelling the learner as improving or declining.
- The reflection UI shows **one evidence-triggered question**, selected from the week's high-confidence errors, supported-versus-independent gap, mistake closure, delayed revision, or available independent evidence. An empty week instead asks for one small start action. The single answer is written to the existing `next_week_intention` field; previously stored `proud_of` and `challenge` values are loaded and submitted unchanged for backward compatibility. Reflections remain keyed by `student_id` plus ISO Monday in the existing `weekly_reflections` SQLite table, remain isolated between students, and are removed when the student profile is deleted.
- `GET /api/tutor/weekly-report` returns the current report. An optional `week_start=YYYY-MM-DD` selects one of the available Mondays. `POST /api/tutor/weekly-report/reflection` upserts the authenticated student's reflection for an available week. Both routes require the normal student session identity.
- `GET /api/tutor/weekly-learning-summary?days=7` remains the backward-compatible rolling summary used by existing Dashboard and parent surfaces. It is not the archived calendar-week report.
- Activity duration remains an observed timestamp-window estimate, not stopwatch study time. Isolated events add no invented duration, and activity-day grouping uses Brisbane local dates.

## Adaptive diagnostic

- The diagnostic workflow selects from the active subject/year or course scope and branches by response evidence.
- Each area runs a one-band staircase: a correct answer moves one band harder, an incorrect answer one band easier. Item selection is seeded per student and prefers a new topic and an unseen question.
- Each area gets an ability estimate that uses the item difficulty band and a guess floor for multiple choice. Answer order does not change it. The result page groups areas into **Start here**, **Building**, and **Secure** and gives one starting topic.
- “I haven’t learned this yet” is scored as not known. Each area result shows these answers as **not learned yet**, apart from wrong answers. An optional “How sure?” choice is stored; a sure-but-wrong answer moves that topic to the front of its area. Diagnostic answers never create Error Book entries.
- A failed Year 8–10 area gets one previous-year check, reported separately. A valid result puts its start topics first in forward recommendations and moves secure areas last; mastery and prerequisite gates still apply.
- One area can be retested at any time without the 45-day cooldown; only that area changes. The parent dashboard shows each area with its previous result.
- Deterministically scorable items are marked locally. Open text and rubric responses may use the configured LLM.
- A response that cannot be scored safely is marked `grading_deferred`; it is excluded from mastery and mistake calculations rather than treated as incorrect.
- `scripts/check_difficulty_calibration.py` compares authored difficulty bands with real accuracy and lists items to relabel.

## Practice papers and mock exams

- Generate subject-aware papers or use imported papers from `data/exams/`.
- Available generated-paper presets include mixed sets; Maths NAPLAN numeracy, fluency, and AMC challenge sets; English literacy/reading/language sets; Science inquiry/data/extended-response sets; and QCAA senior Maths Paper 1/Paper 2 practice sets.
- Exam sessions use a server deadline, resume support, and late-submission handling based on the last saved answers. Autosave is single-flight in the browser: while one save is in progress, only the newest pending full snapshot is retained. Every save, including page-hide keepalive, carries a monotonically increasing revision; the backend treats equal revisions idempotently and ignores stale revisions, while submission remains terminal.
- The setup page shows the newest unsubmitted exam of the selected scope (`GET /api/exam/active`) with **Resume exam** and **Discard**. Resume (`POST /api/exam/resume`) keeps the paper order, the saved answers and the server deadline, so time is not given back or taken twice. Discard (`POST /api/exam/discard`) asks first and deletes only an unsubmitted session. A reload in the same tab reopens the exam (`sessionStorage` key `qld_exam_active_v1`). The status shows **Saved** only after the server confirms a save; a stale save shows **Not saved** with **Reload**.
- After submit, each review item includes the answer-free question view (stimulus, table, image, parts, choices) and the worked steps. These are added to the response only. Topic chips show curriculum names (`topic_names`) with the code in small text; senior papers group the breakdown by curriculum topic.
- Results distinguish scored responses from responses pending parent review. The displayed bands are practice indicators, not official grades.
- A blank answer scores 0 and shows **Not answered**. It is not an Error Book mistake, and it does not change mastery (BKT) or error patterns.

## Writing Hub

- Supports formative Years 7–10 NAPLAN-style narrative and persuasive feedback and Years 11–12 QCAA-style writing criteria.
- Includes writing timers, topic selection, draft history, revision comparison, criterion feedback, and grammar-remediation links back to practice.
- The in-progress browser draft is one versioned JSON document under `qld_tutor_writing_document_v1`. Phase, topic and year, all draft text, timer state, pending assessment ID, and revision anchor are serialized together and committed with one `localStorage.setItem`, avoiding partially updated multi-key state.
- Legacy Writing draft keys are deliberately deleted on first mount and are **not read or migrated**. Any unfinished draft saved by an older build is discarded after this release. A successfully persisted portfolio entry clears the current document; `qld_tutor_last_writing_practice` remains a separate navigation preference.
- Revision comparison is **text-level only** (length, sentences, vocabulary). It does not re-score the draft; run **Assess** again after editing to refresh criterion scores and overall feedback.
- Without a server LLM, local text pre-checks still provide limited feedback. The bring-your-own-LLM flow can export an assessment prompt and import the returned JSON through the same result parser; transfer is manual copy/paste.
- Live and bring-your-own-LLM results pass the same canonical rubric validation. Invalid, incomplete, non-finite, out-of-range, non-integer, or mismatched criterion scores are not clamped or filled with zero; they remain unscored or follow the retry/recovery path.
- Provider timeouts, transport failures, and unavailable or pending results keep the current draft available for retry. They do not create an incorrect mark, Error Book entry, mastery evidence, or portfolio score.
- A topic with a word limit needs its minimum word count for a score. The server uses the authored topic minimum, not a value from the browser. A shorter draft gets short-draft feedback that is not scored; the editor shows how many more words are needed.
- A quote of four or more words in criterion feedback that is not in the draft or the task texts gets a **Not found in your draft** warning. In-text highlights are labelled **Error** (for example spelling or punctuation) or **Suggestion** (style and word choice).
- Senior analytical tasks on a prescribed text are labelled EA-style practice; the persuasive speech is IA1-style. Senior tasks show the syllabus version, and prescribed-text tasks show a note that the text lists change between cohorts.

## Parent and student identity

- Anonymous use creates a per-browser student UUID and signed session token. Progress is still saved by the installation for that anonymous profile, but access to it depends on retaining this browser's local storage; another browser/device receives a different anonymous profile.
- Optional name/password registration stores a bcrypt password hash in `data/credentials.json` and maps login to a stable `student_id`, enabling the same learner profile on another device connected to this installation. The student entry screen therefore describes anonymous use as **Continue on this browser**, not as an unsaved session.
- The Parent Dashboard requires the server-side `PARENT_PASSWORD`. A successful login creates a short-lived parent token (2 hours) bound to the active student.
- The Parent Dashboard and Bank Review lock after 15 minutes without input. The check uses the last input time, so a computer that wakes from sleep locks on its first input. **Lock** clears the typed password, and **Lock** and the home-page **Sign out** remove the parent session from the tab.
- Parent tools include progress and daily summaries, assessment readiness, exam and writing history, pending open-response reviews, next-step suggestions, and local student profile list/switch/delete actions.
- Switching the active student clears the parent session, so the parent must unlock the dashboard again.

## Bank Review

- Bank Review is parent-gated and supports uploading exercise/exam JSON, opening a production exercise bank, and reviewing the imported items before anything is written to disk.
- **Save edits** updates only the in-memory review session. The editor can change the question, answer, steps, status, difficulty, reasoning rubric points, multi-part sub-questions, sample reasoning, `diagram_data`, `diagram_description`, and image reference. `diagram_data` must be a JSON object; `diagram_description` is the accessible text description of the visual and can be cleared by saving it empty.
- Persistence is explicit and separate from editing: **Download updated JSON** exports an uploaded session, **Save bank** replaces the selected production bank only after confirmation and verified-backup/reload checks, and **Save exam** writes an imported paper under `data/exams/` with the same backup protection for existing files. Invalid items block the relevant durable write.
- Review sessions are temporary server-memory state with a maximum of **8 active sessions** and a **4-hour TTL**. Use **Close Session** to discard unsaved changes immediately and free a slot; otherwise an expired session is purged automatically. Closing a session does not write its edits to a bank or exam.
- See the [Bank Review durability notes](../bank-review.md) for per-file atomicity, append behavior, and imported-exam storage boundaries.

### Maths Lab P4/P5 resource controls

The Lab keeps interactive rendering bounded rather than retaining an unbounded simulation history:

- The catalogue currently has **45 activities across six tabs**; all scenes use the shared bounded rendering and Learn contracts. Six of them cover visual topics added for Years 7–12: a one-dimensional **number line** (order, midpoints, inequality solution sets), **parabola transformations** in completed-square form, **angle reasoning** (parallel lines, triangle and polygon angle sums), **exponential growth and logarithms**, **stationary points and concavity**, and **area between two curves**.
- Statistics retains and renders at most **40 data points**; probability simulation is capped at **200 deterministic trials**.
- Direction fields are capped at **13 × 13 = 169 short line segments** (the current Mafs `Plot.VectorField` scene renders one field primitive rather than 169 React segments).
- Polar/parametric and other sampled curves use a Mafs sampling-depth cap of **8**.
- Newton iterations and trapezoidal-rule partitions are capped at **20**.
- **Learn marking has three layers**: exact match after character normalisation, numeric tolerance, then — only for steps that opt in through `equivalence` — deterministic numeric-sampling expression equivalence. That third layer lets a step ask for a derivative, tangent rule or parametric gradient and accept any algebraically identical form. It uses a self-contained parser with no `eval` and no added dependency, and identifiers are restricted to the step's declared variables plus known constants and functions, so junk such as `4abc` is still rejected.
- **Completion is stricter than before.** An activity reports success only when *every* core step is correct, rather than a bare majority of steps. Hints stay freely available and carry no penalty: using one does not change the recorded result or withhold the extension challenge.
- The **extension challenge** is withheld until all core steps are correct. It asks a reverse, condition-finding or counter-example question rather than repeating the taught procedure, and failing it never withdraws the recorded core result.
- **Every activity supports a repeatable variant, and it changes the graded steps.** All 45 activities regenerate their three core steps together with the typed `sceneData` their canvas reads back, so the prompt and the drawing can never disagree. The extension challenge is regenerated separately with a rotating question form. One activity — the tree diagram and two-way table — renders a single fixed scenario, so its variant rotates the three questions asked about that scenario rather than the digits. Completion remains keyed only by `activityId`.
- Only the active Lab tab and selected Explore scene are mounted. Statistics, Geometry, and Linear Algebra extensions are loaded through separate client chunks; switching scenes unmounts the previous SVG tree and temporary arrays.
- The Lab does not use continuous animation loops or interval timers, does not persist trial history, and cleans up its short-lived copy-feedback timeout on unmount. Browser module caches may retain downloaded JavaScript, but DOM/SVG and scene state do not grow with tab switching.
- Activities with a confident curriculum mapping expose topic-aware deep links from the home page, Guided Practice extensions, Dashboard, and the Lab directory; these links remain independent of mastery/BKT evidence.

### Interactive Science Lab

An independent `/science-lab` page for AC9 Science Years 7–10. Its scope remains selective: it provides interaction that ordinary question cards cannot host rather than claiming complete coverage of all 75 Years 7–10 Science topics.

**Admission rule.** A topic becomes a Lab activity when the required interaction reaches **L3** (continuous variables plus time/state), **L4** (student construction or system perturbation), or **L2 with a meaningful counterfactual**. Purely static cell labels, pre-filled Punnett squares, static Sankey diagrams and worked accuracy/precision examples remain in exercise cards. Their Lab counterparts are admitted only when the student changes a functioning system, generates data, compares linked representations or tests a counterfactual. `science-lab-activities.test.ts`, `science-lab-interactions.test.tsx` and `science-lab-expanded-contracts.test.tsx` enforce the threshold, real-control mapping, reveal gates, accessible SVGs and resource budgets.

**Teaching and completion contract.** Learn mode runs Orient → Predict → Manipulate → Observe → Explain → Transfer. Prediction-bearing quantities and accessible descriptions remain hidden until a prediction is submitted; a prediction does not need to be correct. Durable completion additionally requires a student-scoped Inquiry Notebook containing prediction reasoning, independent/dependent/controlled variables, every inquiry stage, at least three observation snapshots with two distinct data states, claim–evidence–reasoning, and a selected model limitation. If local persistence is unavailable, the draft remains editable in the tab but the UI does not announce durable completion.

**Evidence boundary.** Lab work never updates BKT or mastery. Notebook keys use `qld-science-lab-inquiry-notebook-v1:<studentId>:<activityId>` and completion uses `qld-science-lab-completed-v1:<studentId>`; legacy unscoped records migrate once to the active profile. These records stay on the current browser and do not sync across devices. The independent transfer exercise is the only intended mastery evidence and enters the existing practice/marking path with the originating year and topic where available. Science Lab adds no backend router, table or event API.

**Resource and rendering controls.** Renderers are inline SVG or native Canvas and are resolved through a lazy registry so exactly one scene is mounted at a time. `SCIENCE_LAB_LIMITS` caps 250 particles, 200 population individuals, 60 generations, 300 SVG primitives, 120 graph points, 200 stochastic trials, one animation loop, zero workers and zero WebGL contexts. Models use explicit seeds where stochastic behaviour is instructional, publish honest relative/teaching units where they are not calibrated, disclose limitations, pause hidden work, and do not auto-play under `prefers-reduced-motion`. Drag interactions have keyboard/numeric alternatives, and only dedicated drag targets suppress browser gestures.
